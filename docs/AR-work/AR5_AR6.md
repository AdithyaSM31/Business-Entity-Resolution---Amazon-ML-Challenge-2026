# AR-5: Calibration & Expected F0.5 Selection

## Overview

AR-5 improves the final match selection using:

- Isotonic probability calibration
- Expected F0.5 selection
- Optional exclusivity
- Optional has-match gate
- Macro F0.5 comparison

## 1. Probability Calibration

Uses `IsotonicRegression` to calibrate model probabilities.

- Calibration is cross-fitted on OOF predictions.
- Brier score is measured before and after calibration.

## 2. Expected F0.5 Selection

For each S1:

1. Sort candidates by calibrated probability.
2. Consider selecting `0` to `n` candidates.
3. Calculate expected F0.5 for each option.
4. Select the option with the highest expected F0.5.

At most 50 candidates are considered.

If selecting nothing is better, the prediction is:

`S1 → []`

## 3. Poisson-Binomial DP

Expected F0.5 is calculated using Poisson-binomial dynamic programming.

- `A` = true matches selected
- `B` = true matches not selected
- `k` = number of selected candidates

For `k > 0`:

`F0.5 = 1.25A / (0.25(A+B) + k)`

## 4. Exclusivity

When enabled:

- A candidate can belong to only one S1.
- The highest-probability S1 keeps the candidate.
- Ties are dropped.

Exclusivity is used only when supported by the BH-1 ground-truth check.

## 5. Has-Match Gate

An optional Logistic Regression gate predicts whether an S1 has any true match.

Features include:

- Maximum probability
- Second-highest probability
- Number of probabilities > 0.5
- `fc_n_close` when available

If the gate rejects an S1, its prediction is `[]`.

## 6. Method Comparison

AR-5 compares:

1. Threshold
2. Expected F0.5
3. Expected F0.5 + Gate

The methods are compared using Macro F0.5 on OOF predictions, with optional LOCO comparison.

## 7. Output

Selected parameters are saved to:

`models/<run_id>/postprocess.json`

## 8. Tests

Run:

`python -m pytest tests -v`

## Flow

Model probabilities  
↓  
Isotonic calibration  
↓  
Threshold / Expected F0.5  
↓  
Optional gate  
↓  
Compare Macro F0.5  
↓  
Best selection method  
↓  
Final match lists


# AR-6: Error Sheets

## Overview

AR-6 creates error reports from the out-of-fold predictions and the selected postprocess parameters.

It helps identify which matches the model gets wrong and why.

## 1. False Positives

Creates:

`docs/errors/<run_id>_fp.csv`

Contains the **100 wrong predicted pairs with the highest probability**.

## 2. False Negatives

Creates:

`docs/errors/<run_id>_fn.csv`

Contains up to **100 true matches that were missed**, split into:

- `not in candidates` — the true pair was never generated by blocking.
- `in candidates but not selected` — the pair was available to the model but postprocessing did not select it.

FN rows are sorted by probability from **lowest to highest**.

## 3. Error Sheet Columns

Both files include:

- `s1_id`
- `cand_id`
- `prob`
- rank within S1
- country
- source
- raw name and address of both records
- `name_core` of both records
- `addr_norm` of both records
- entity's true match count

## 4. Entity-Level Loss Breakdown

The script also prints points lost from:

- Singletons that were incorrectly matched
- Non-singletons that were left empty
- Partial match sets

This shows which type of entity-level error contributes most to the F0.5 loss.
